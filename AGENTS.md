# DQMJ3 Professional reconstruction

The owner requested public development of the actual reconstruction, source, tooling, research, documentation and history on 2026-11-06, following pokebw2's public-source/private-original-input pattern. Original ROM archives, CIAs, executable images and extracted original game payloads must not enter the public repository or public artifacts. Hybrid images and original-gap objects containing retained original bytes remain private. Original inputs may be supplied through owner-controlled private storage to trusted verification jobs; fork/public compilation must not receive private inputs or credentials. Keys and saves remain private. Audit tracked files, reachable history, logs and artifact paths before publication; publish the real development work rather than an empty report repository. Original inputs are immutable. Write disposable game/save copies and emulator profiles only under work/. Do not alter DQMJ2 Pro or Monster Fieldnotes. Use project-local tools and dependencies; no global PATH, Java or policy changes. All temporary clones and independent replay roots belong under work/.

The target identity is the measured owner archive and its separately identified base and update contents. Retail identity, translation status, compiler family/version, script formats and engine lineage require evidence. Never substitute community labels for measurement. Native executable inventory, script inventory and assets are separate.

Use ordinary readable C/C++ for recovered game logic. Assembly requires evidence of original assembly or unavoidable low-level behavior. No instruction/register/object/relocation patching, embedded executable blobs or compiler-output generation receives source credit. Name functions and variables for what they do and document the code in place; keep files at most 500 physical lines. Unmodified third-party code and generated reports are separate.

Every call into Nintendo system services goes through a named interface under platform/. Reconstructed game code must not call nn::, nw:: or raw system primitives directly. This costs nothing while the tree is small and cannot be retrofitted once tens of thousands of functions exist; it is what makes a port to another platform a matter of implementing one header rather than searching twenty-six thousand functions.

Parallel agents may research or prepare independent packets with frozen input/tool hashes, canonical build/program/module/address/ARM-or-Thumb identity, complete instruction/pool extents, exclusive output paths, ABI and dependency closure, reproduction argv, negative attempts and unsupported paths. One coordinator owns shared schemas, registries, evidence publication and integration. Workers never edit another lane's files or run shared-output checks. Keep coupled routines together. Claims are explicit; a task result is not acceptance.

Report exact object bytes and relocations, real source-linked bytes, bounded behavior, independent clean replay, platform execution and source-only executable/container status separately. Compiler similarity, heuristic function counts, original-byte roundtrips and retained gaps receive zero recovered-source credit. Missing artifacts or skipped modules fail completeness checks. A bounded test is not a universal equivalence proof. Preserve failures and effective tool identities, including package metadata/native-library discrepancies.

Scope a unit of work to what one contributor can carry to a green merge, and no smaller. A pull request that genuinely moves the needle is worth more than three tidy slices of it. The ceiling is measured rather than declared: while the first-pass CI green rate stays above two thirds, enlarge the batch; when a change needs repeated repair rounds, that is the signal to scope back. The concurrent pull request limit exists to keep review and merge serialised, and it is not a statement about how much one change may contain.

Start with archive/container verification and loader mapping, then compiler identification. Lock native denominators only after executable inventory review; inventory filenames alone do not prove executable completeness. Interpreted scripts retain their own denominator and original embedded source is not newly reconstructed source.

Use docs/2026-11-06-project-charter.md and docs/2026-11-06-roadmap.md for intent and current next work. Joker 1 remake research is a separate future capability track. Never change original J3 mechanics merely to make a prospective Joker 1 scene work. Emulation must be silent and use isolated disposable profiles; qualify debugger behavior before capturing evidence.

The active objective is a complete recreation the owner's own copy can build: every function present as source, the whole image linked from compiled source with no retained original bytes, and the result byte-identical to the original. A properly equipped user supplies their own game image; the repository supplies the source and the build. Byte-identity is how fidelity is known, not a separate goal. Report compiled-from-source bytes and retained bytes separately and make the retained count the headline. The owner selected an independent public/open-toolchain route on 2026-11-06: proprietary compiler or Nintendo SDK availability is not a prerequisite, though the measured original compiler may be pinned as a build input where it can be fetched and verified. Keep exact matches, behaviour-only drafts and platform component builds distinct; platform builds come after the recreation, not before. Native Windows and Android targets remain a later goal.
