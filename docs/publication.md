# Publishing the reconstruction repository

The owner authorized publication of reconstructed source, project-owned tools, research and derived validation evidence on 2026-11-06. The publication target is this actual repository with its development history. Retain the C/C++ reconstruction, platform components, tests, tooling, research, acceptance packets and documented failures.

Original archives, CIAs/ROMs, extracted executable images, shipped scripts/assets, keys, saves, retained-original objects and hybrid images remain private. The repository's ignored input/tool/work/build/generated directories are not publication inputs. A source/report export must not silently replace the actual development repository.

## Audit before pushing

From the repository root, using a public Python runtime with the standard library and Git:

    python toolscripts/publication_audit.py --output work/publication-audit/preflight.json

After the coordinator has reviewed and committed the intended source changes, run:

    python toolscripts/publication_audit.py --require-clean --output work/publication-audit/final.json

The audit writes only beneath ignored work/publication-audit/. It performs no staging, commit, deletion, history rewrite, network access, remote creation or push. Keep the final report outside the checked tree so creating the receipt does not change the publication revision. A later commit requires another audit.

The JSON report binds the immutable HEAD revision, ref/index/status snapshots, checked blob identities and current file hashes. passed means the requested content checks completed without findings. publicationReady additionally requires a clean repository. The --require-clean mode makes a dirty publication candidate fail. A preflight can inspect safe uncommitted source while publicationReady remains false.

## What is checked

Every commit reachable from all refs and HEAD contributes its complete file tree and historical path aliases. Every reachable Git blob and staged index blob is read and checked against its Git object identity. Current tracked files and nonignored untracked files are also inspected, including a staged payload whose current working copy was overwritten. Commit/tag messages and ref names receive credential checks. Ref/index/status changes or changed checked files during the run fail the snapshot.

Private input/build paths, credential filenames and restricted payload extensions fail. Format signatures identify containers and binaries even after renaming. Hashes from measured original-input/asset metadata identify known whole game payloads, including original plaintext scripts under misleading filenames. Large hex/base64 regions receive additional payload checks. The original archive and game images are not opened for this publication audit.

The credential checks detect supported service-token forms, plausible credential assignments, signed JWT candidates, private PEM blocks and additional private-key containers. Findings contain rules and locations rather than secret values; sensitive filenames are redacted. Ordinary documentation references and public certificate material do not receive a private-key finding merely for discussing keys. Public certificate handling does not suppress unrelated token findings in the same document.

Missing or oversize objects, unknown binary material, Git LFS pointers, symlinks, submodules, shallow history and history-replacement mechanisms fail closed. No fixture generated by the leak tests contains an account credential or original game payload; disposable synthetic histories stay under ignored work/publication-audit/tests/.

## Review findings and limitations

A finding blocks publication until it is understood and the exact candidate is checked again. Deleting a leaked file from the current tree leaves its historical blob reachable. If actual secret or original-payload exposure is found, the coordinator must address that history deliberately; this tool never rewrites it automatically. Do not publish a failed security report before reviewing it, even though the scanner avoids printing matched credential values.

Pattern and format checks cannot prove absence of arbitrary encodings, novel secret formats, or unattributed plaintext fragments. Known original hashes complement manual provenance review. Bounded instruction/header bytes in derived validation metadata remain part of the evidence; they do not authorize distributing whole original files. The report does not approve ignored files, unreachable objects/reflogs, future commits or external CI artifacts.

Public CI must use complete checked-out history and must keep original-dependent checks separate from checks that run entirely from public source. Build artifacts require their own explicit source/provenance review; a tracked-tree/history pass does not authorize uploading a hybrid image, original-gap object, ROM, private signing key or input cache. The coordinator owns the CI artifact policy and final remote publication.
