# Genuine source call graph integration

`toolscripts/module_link_graph.py` extends the earlier closed-leaf linker contract without changing the frozen leaf receipts. It supports independently owned function sections containing named `R_ARM_ABS32`, `R_ARM_REL32`, `R_ARM_THM_CALL`, `R_ARM_CALL`, `R_ARM_JUMP24`, and `R_ARM_THM_JUMP24` relocations. Every actual relocation and its source or retained-original dependency must be declared. Other relocation forms and anonymous section references fail explicitly.

The compiler object and complete section are frozen by hash before linking. Instruction, literal-pool and padding extents are explicit and sum to the complete section extent. LLD resolves the actual compiler relocations at measured native addresses. The complete resulting module image, function symbols and dependency resolutions must match their measured identities. No instruction bytes, relocation bytes or object files are patched. Any unexpected veneer, wrong dependency or alignment change fails the full-image comparison.

Retained function and data dependencies are typed assembler aliases with ordinary linker symbol assignments. They remain original inputs and earn zero source credit. The hybrid output, original-gap assembly/object, and linked image stay under private `work/`. The tool grants no acceptance, universal behavioral proof, source-only module or game-build status; independent source, boundary, ABI and behavior review remain required.

The regression fixture compiles ordinary C caller/callee logic, links a source reference with real LLD, and independently repeats integration using compiler relocations. It checks source and retained callee provenance, missing and altered manifests, unowned source dependencies, genuinely compiled wrong logic, redirected calls, and incomplete section accounting. Its input image is synthesized from the fixture's C, never a game binary, and earns no game-source credit.

The contract follows [Arm's ELF ABI specification](https://github.com/ARM-software/abi-aa/blob/main/aaelf32/aaelf32.rst), including call/jump interworking and linker veneers, and [LLD's documented linker-script behavior](https://lld.llvm.org/ELF/linker_script.html), including typed symbol aliases and explicit output addresses. These primary sources were checked on 2026-11-06. Actual behavior is additionally qualified with the project's frozen Clang/LLD21 binaries; the documentation's current LLD version is not substituted for those pins.

This capability is not yet used by the ByteMatch production generator. Admitting relocation-bearing or literal-pool functions will also require their reviewed cohort, compiler profile, source object construction, and instruction-versus-owned-text accounting to be wired into that generator. Existing leaf progress remains unchanged by this tooling.
