See [Microsoft's contract](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitonaddress). Android native packaging must retain 16 KiB ELF segment alignment, compatible dependencies and runtime page-size handling; aligned linking alone does not prove execution on a 16 KiB kernel. See [Android's page-size guidance](https://developer.android.com/guide/practices/page-sizes). For separate handheld displays, a future presentation backend must use each display's own context and handle removal and activity pause/resume, as specified by [Presentation](https://developer.android.com/reference/android/app/Presentation). Older Android devices need the compatible display-listener overload rather than assuming API 36 event APIs; see [DisplayManager](https://developer.android.com/reference/android/hardware/display/DisplayManager). These are platform implementation requirements, not recovered game logic or claims that the current SDK component renders a game.
