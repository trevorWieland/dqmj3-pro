# Bounded queue admission

Seven complete canonical bodies account for 1,628 instruction bytes: manager
construction, asynchronous request forwarding, queue insertion and clearing,
worker execution and finalization, and manager destruction. Their ordinary C
implementations receive medium-confidence working-C admission after independent
committed replay. Exact matching remains 412 functions and 5,128 bytes.

The replay passed 120 pipeline tests, all 990 native artifact comparisons and
63 complete logical original/source/copied case files. It rejected 20 applicable
normally returning wrong-source checks. ARM32 pointer narrowing is explicitly
inapplicable, rather than counted as a rejection. Eleven caught input/library
attempts remained persistent failures, and nine frozen observer tests passed.

Queue links and counts use the recursive mutex. Running/current fields are
portable atomics. Frozen request066 ready/error/payload fields remain ordinary C:
observation and destruction require before-start, paused-event acquisition or
joined state. Arbitrary concurrent task polling is unqualified. Allocator,
selector5 filesystem and normal thread-create/join dependencies retain their
measured domains. Terminal service errors and missing/predicate-false original
PCs are recorded explicitly. The partial `0x15e304` join helper receives no
independent admission. The original asynchronous read-error buffer leak remains.

The coordinator independently rechecked five actual Thor pthread captures against
fresh original ARM graphs and budgets. All handles retired after join/close.
The captured ARM64 library and uncompressed APK entry match their declared hashes
and have 16 KiB ELF/ZIP alignment. The physical Thor kernel used 4 KiB pages;
physical 16 KiB-kernel execution, private OS-stack byte equality, historical
scheduler equivalence, full filesystem/bootstrap and whole-game builds remain
unproved. This evidence does not establish an overall confirmed source percentage.
