# Portable reference access

Function prototypes have a 12-byte target reference prefix; collectable objects have a 20-byte reference header with list links. Their native equivalents are 24 and 40 bytes. Shared offsets do not make these distinct C object types interchangeable. The portable VM must access each object's actual declared type or use explicit byte representation access for the shared scalar fields. WG14's [C11 draft N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), sections 6.5, 6.3.2.3 and 6.7.2.1, defines the relevant access, conversion and first-member rules.

The provisional Execute checkpoints retain zero whole-root source credit. Their observed ARM and native fixtures do not establish a general aliasing contract for every heterogeneous reference value. Frozen lifetime components qualify compatible complete reference objects; an actual prototype must not be treated as a complete collectable merely through a cast. Prototype finalization remains a separate recovery dependency.

The portable successor should load/store the vtable pointer and unsigned reference count through byte copies into correctly typed locals. Target offsets are 0 and 4; native offsets must be measured and statically checked against both declarations. Reference arithmetic, publication order and callback reload points must preserve the original behavior. A typed callback bridge may receive an opaque pointer through its exact declared signature, then convert to the actual object type before accessing members. Incompatible function-pointer casts are excluded.

The change must cover assignment, stack/value vectors, container members, saved frames and teardown. Routing only Execute through a safe helper leaves direct accesses inside its dependencies. Portable successor implementations therefore need explicit build selection and their own original/ARM/Windows/Android qualification. Frozen matching providers remain unchanged; each portable operation must have one selected implementation.

Qualification should include actual small prefix objects beside canaries, complete collectables, mixed ownership, callback-observed ordering, width/alignment checks and genuine normally returning wrong-source controls. Sanitizers supplement the C type/access review. Whole-VM or game status remains false until the complete dependency graph and its execution are reviewed.
