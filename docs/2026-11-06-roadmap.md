# DQMJ3 Professional reconstruction roadmap

The next milestone is one closed native function packet and a trustworthy map of script-to-native interfaces. The project has verified input identities, independent executable extraction, bounded asset surveys and an isolated compiler/oracle harness. Its initial pipeline also passes an independent replay of committed snapshot `dc486d2` with fresh private input/tool copies. Original compiler identification, complete executable inventory and replay of a future recovered-source packet remain gates before accepted matching credit.

## Immediate reconstruction work

| Work | Concrete result | Acceptance evidence |
|---|---|---|
| Qualify loader map | ExHeader-derived text, rodata, data and BSS; ARM/Thumb entry map | Independent ExHeader comparison, Ghidra import metadata, address checks |
| Close executable inventory | Native program, potential nested modules, scripts, shader programs and custom loaders | Filename and content scans plus loader references; explicit unresolved regions |
| Identify original compiler | Evidence-based candidate ARM compiler/profile and C++ ABI | Startup, exception/RTTI/library patterns, several independent compiled calibration routines; lawful locally available compiler provenance |
| First native packet | A small pure leaf with complete boundaries, callers and declared input domain | Exact source/object/link comparison when available, original-vs-compiled execution and a failing wrong-source control |
| Script interface map | Hash-bound include/load/native registration graph for original `.nut` | Text loader/VM evidence, callsite and registration analysis; no script-recovery credit |
| Format roundtrip | One SARC and one ordinary XBB family | Identical original-member roundtrip, bounded malformed-input controls, unknown metadata retained |
| Reproducible replay | Immutable committed source plus explicit tool/private inputs | Fresh uncached process, complete expected-artifact checks, independent receipt |

Use update VA `0x0069180c` only as the initial unsigned-range-predicate candidate after binding its exact bytes to the update hash. Its source meaning, extents, callers, compiler profile and tested domain remain attached to the candidate receipt. Native-survey candidates are a bounded heuristic queue, not a function census or acceptance ledger.

## Compiler and tooling decisions

CTRTool 1.3.0, pyctr 0.7.6, Capstone 5.0.9, Unicorn 2.1.4, pyelftools 0.33, objdiff 3.8.3 and a minimal Clang/LLD 21 distribution are locally installed and hash-pinned. Original bytes are never patched to force compiler matches. Clang supports harness construction and behavior experiments while original compiler identification proceeds.

Ghidra 12.2 and a compatible JDK are already available locally in the J2 tool installation. Initial headless qualification may consume them read-only with scoped Java settings and project-local output; they must become explicit pinned tool inputs before any accepted replay depends on them. Install a qualified CTR loader only after confirming its supported Ghidra version, region mappings and ARM/Thumb handling.

Evaluate 3dsd in a disposable pilot before adoption. Its original-byte roundtrip establishes splitter/linker behavior, not recovered-source correctness. Require an independent check that every expected module exists and is tested; retain a gross executable inventory alongside any tool-specific progress denominator. Resolve its license before vendoring.

Pin stable [Azahar 2126.2](https://github.com/azahar-emu/azahar/releases/tag/2126.2) when scene-level validation needs it. Qualify GDB pause/resume, single stepping, memory RPC and silent startup first; the research report records debugger limitations. Version 2127.0-rc1 was a prerelease on 6 November. No emulator installation or platform execution is part of this initial milestone.

[3dsrecomp](https://github.com/fearkov/3dsrecomp) and [any3ds](https://github.com/mohammed-hajwani/any3ds) are experimental later runtime/oracle lanes. Generated static-recompilation code is a different product from readable matching reconstruction. Neither upstream's reported progress establishes DQMJ3P compatibility.

## Joker 1 remake capability track

The first useful target is a small Joker 1-inspired test scene using measured J3 engine interfaces and owner-supplied resources. Choose a single room or map, a controllable character, one interaction, one battle transition and a save/load cycle. This tests content loading and control flow before an expansive world conversion.

| Stage | Engine capability | Completion condition |
|---|---|---|
| Resource understanding | Parameter schemas, archive packing, script loaders and native bindings | Extract/edit/repack a disposable resource with preserved unknown fields and verified game behavior |
| Scene loading | Models, materials, animation, placement and collision | A small test scene loads with stable movement, camera, transitions and reproducible inputs |
| Gameplay slice | Event flags, interactions, encounter/battle entry, menus and persistence | One complete deterministic scenario survives reload with explicit mechanics observations |
| Joker 1 adaptation | Content conversion, party/mechanics decisions, UI and progression | Documented adaptation rules plus tested scene and battle fixtures; separate from original J3 source |
| Engine portability | Platform services, renderer, audio, input, timing, filesystem and threading | Explicit platform boundary and regression suite; hardware-specific behavior retained or deliberately adapted |

Joker 1 and Joker 3 differ in content, engine assumptions and mechanics. An asset converter alone does not create a remake. Keep remake experiments outside src/ until the engine interfaces and adaptation rules are measured. Matching J3, running an altered J3 build, and shipping a portable engine have different exit conditions; assign no timetable from current inventory counts.

## Operational constraints

The initial machine had about 4 GB free before extraction and under 2 GB afterward; a later space check showed about 63 GiB free. Streaming intake and selected private samples still avoid unnecessary full RomFS or NDK/Ghidra duplication. The independent replay checks space before materializing explicit input/tool copies. Do not remove unrelated owner files to make space.
