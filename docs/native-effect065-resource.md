# Effect resource CPU successor

This candidate reconstructs the CPU resource preparation around update entry
`0x53fe5c` and its measured vertex, command and texture dependencies. The original
module is the authenticated update executable. The six-body wave065 foundation
remains unchanged. No source or matching credit is granted by this lane.

The canonical constructor retains all 4,572 instruction bytes and 1,143 ARM
instruction addresses. The exploratory joined corpus visited 1,002 of those
addresses; 963 had a satisfied ARM condition. A hook encounter alone does not
establish that a predicated instruction took effect. The remaining addresses and
storage1/2 paths remain unqualified. The constructor source, wrapper, factory and
finalizer are separate from proof of the actual game-facing load/caching caller.

The pointer-free vertex input is 1,936 bytes. Attribute removal preserves format
bytes when the final binding disappears. Command generation preserves inherited
header bits, alignment, raw float-to-24-bit packing and the caller-used end
pointer. These words are device data, never truncated native addresses.

Texture conversion has an independent inverse-tile model and compares statuses,
output, complete initialized caller/provider storage and cleanup order. The
scratch allocator's `0x100` argument is an option enum, not alignment. The fixture
separately supplies aligned backing. The original four-bit in-place path requests
and copies zero bytes while touching packed temporary bytes; its bounded fixture
supplies usable backing for zero requests. This establishes no general allocator
safety property.

The source resource header is 60 target bytes and 112 native bytes. A primitive is
2,072 target bytes and 2,152 native bytes. Original logical allocation requests
remain unchanged; the typed allocator bridge separately supplies physical native
storage. Native pointers remain full width. The platform adapter receives each
allocation role, logical bytes, physical bytes and alignment. No SDK allocator
implementation or startup is credited.

Fresh SPBD offsets remain U32 serialized data. Native runtime sets, references and
emitter views occupy a single expanded set allocation. Overlapping aligned
reference intervals share typed storage; repeated emitter offsets share one
runtime emitter identity. The bridge retains the original allocation count and
logical set budget. Native bookkeeping and pointer representations are observed
explicitly, rather than writing widened pointers into file fields. The qualified
files have null unwritten runtime pointer slots and valid bounded offset tables.
Misaligned overlapping reference tables, corrupted counts, repeated construction
of an already fixed-up file and arbitrary mutation by other owners are outside
the current contract.

The observer retains full raw resource and pointer-free primitive bytes. It
compares typed fields, alias identities, every raw payload allocation, untouched
native ABI padding, immutable caller system/options/table/pool bindings and
physical allocation guards. Only the specific complete original pointer-fixup
fields are projected out of the borrowed-file comparison. Numeric material words
remain compared exactly. Material index bytes are signed: original LDRSB
witnesses are `0x540f38`, `0x540f3c` and `0x540fd8`. The applicable write envelope
must remain in the initialized borrowed file. No universal MATC envelope or GPU
shader eligibility claim follows.

The source platform services distinguish real host pointers from separately
registered U32 device words. CPU storage0 fixtures use a coherent host memory
provider. Transfer queues are explicitly fail-closed and uninvoked in this
corpus. The reference executes the actual original cache-flush SDK body and its
discontiguous tail through SVC32. A declared reference service validates handle
`0x6501`, TLS command `0x1f0082`, the measured process pseudo-handle, a live
allocation and its initialized byte extent before recording the request and
returning service success. This is a bounded reference OS contract, not genuine
GSP initialization or native GPU execution.

The complete graph builds from ordinary C for ARM, real Windows and high-address
AArch64. The Windows profile uses the pinned Clang21
`-mno-incremental-linker-compatible` option; no compiler output is patched. The
freestanding byte-clear runtime is authored platform support and earns zero
original SDK/source credit. The source-only copy contains only this lane's C/H
and its unchanged shader foundation dependency; compiler/runtime tools are reused
outside that tiny copy. Source execution maps no original executable helper or
image.

Returning wrong-source controls change a set name, material device-word units,
native set budget and decoded-texture release route. They return normally before
the semantic observer rejects them. The positive joined corpus separately

converted/borrowed/invalid textures, scratch failure, primitive buffers and
command construction. Provider backing is retained for private observation; that
does not permit a game caller to use freed objects, establish allocation reuse or
qualify unbounded sessions.
