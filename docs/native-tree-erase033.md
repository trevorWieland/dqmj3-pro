# Typed tree erase family033

Seven existing canonical update functions have byte-identical 1,632-byte ARM bodies:7669a4, 767400, 767f88, 7689d8, 77700c, 77da78, 77e490. The pre-source claim checks complete instruction extents, identical bodies, no external calls, no PC-relative data and internal-only immediate branches against the immutable update image. No inventory entries are added.

The reconstruction uses ordinary C node/control/iterator types, successor selection, node transplantation, rotations, color repair and a recycled-node list. It has no instruction/register interpreter or embedded executable bytes. `tree_erase.c` owns unlinking and recycling; `tree_rebalance.c` owns rotations and repair. The LLVM libc++ tree implementation was consulted as an algorithm reference; no reference source was copied. Actual original execution governs the result, including the nullable-child replacement rule, preserved removed-node fields and successor/color exchange. This is a measured colored-tree routine, not a claim that every input/output satisfies an inferred library's abstract balancing invariants.

Measured target fields are node color byte 0, parent 4, left 8, right 12; control recycled 4, sentinel 16, count 20; iterator pointer 0. The original keeps R0 unchanged and returns the original output iterator pointer. An independently compiled layout probe establishes the source native layout: 32-byte node, 40-byte control, 8-byte iterator. This is an explicit port view, not a claim about an unrecovered complete native game class. Unknown bytes and padding remain untouched. Output may alias the input iterator; iterator storage otherwise stays separate from nodes/control. Non-NULL iterators/control and a coherent owned acyclic graph are preconditions.

The deterministic 2,048-case corpus contains 0–48 active nodes, all color bits restricted to 0/1, empty/end iterators, arbitrary rooted ordered shapes, aliased/distinct iterators and zero to two existing recycled nodes. Parent links, reachability, ordering, sentinel extrema and declared bounds are validated before execution. Each fixture executes all seven original bodies and three independent source builds:ARM11MPCore, real Windows x64 and an AArch64 CPU model with real pointers above 4 GiB. Source ARM must reproduce the complete 4,096-byte caller arena. Native layouts compare every typed node/control/iterator field plus preservation of all other caller bytes; raw bytes are not claimed equal across pointer widths. Native raw arenas remain private for independent review. Guards reject undeclared reads/writes, source code escapes and private stack reads before writes; model saved registers and floating environments are checked.

Each original body exercises 406 of 408 instruction addresses. Two unvisited four-byte branches follow a near-child rotation and test whether its newly published pivot is NULL. The pivot was already dereferenced and is stored in the sibling slot under coherent parent/child links; the NULL path requires an inconsistent graph. Static instruction witnesses and hashes record these domain exclusions separately. They are not described as executed, universal proof or branch-outcome coverage.

Six compiled wrong implementations must return normally and be rejected on all three source targets: wrong successor, omitted count update, omitted removed-color exchange, dropped recycled tail, wrong final repair color and overwrite of an aliased input. Twelve tests cover actual cross-target execution and the graph/memory/ABI guards. The AArch64 PIC shared object has independent 16 KiB load/RELRO checks. This does not establish Android OS, AYN Thor hardware, physical 16 KiB-kernel, whole-game or universal equivalence results.

Reproduce with `tools/python/Scripts/python.exe toolscripts/tree_erase033_qualify.py --output work/tree-erase033/qualified-v2` in an owned checkout with the pinned tools and privately extracted update inputs. Use a new output directory. A frozen ready packet is produced only after execution, controls, tests and input guards pass; coordinator review and a separate immutable clean replay are still required for catalog admission.
