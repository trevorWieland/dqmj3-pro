# Source-link metadata pins

Adding a generated ByteMatch name mapping changes the whole names-header hash. Existing renamed-function proofs must retain valid header pins before a complete replay starts. Run `generate_source_names.py --check`, then `refresh_functional_source_names.py --previous-header-revision <reviewed-predecessor> --output evidence/verification/<new-receipt>.json`, followed by the complete strict `functional_report.py` validation.

The refresh requires the predecessor header to remain an exact prefix, preserves all existing mappings, and rejects a header used by compiled C. It changes only active functional alias metadata and its registry hashes. Frozen lane packets, runtime sources, behavior records, confidence and the strict validator remain unchanged. The receipt preserves both header identities and every changed packet identity. A previous receipt is never overwritten during another mutation.
