# Portable Squirrel call boundary

This successor translates the complete measured Call controller at `0x0017ffac` and NativeCall controller at `0x00196f6c` using the actual named opaque object families from waves 011–020. It also composes the measured array native controller at `0x001b33dc`. These canonical bodies already have earlier bounded reconstructions; this packet requests no duplicate interval or matching credit. Whole Execute, complete VM, native game, device execution and 95% source completion remain unclaimed.

`measurement.json` binds the canonical update module and census. Call owns 500 instruction bytes plus its four-byte literal. NativeCall owns two instruction ranges totaling 1,540 bytes; its 64 intervening/trailing bytes contain two measured byte-string messages, alignment and literal words. The array controller owns 340 instruction bytes. No original bytes, executable address tables or original helper fallback are embedded in product source.

## Provider selection

The production selection is `vm_call.h`, `vm_storage.c`, `generic_call.c`, `native_call.c`, `call_frames.c`, `array_native.c`, `lookup_call_adapter.c`, `error_service.c` and `literal_format.c`. The last file implements only literal messages containing no `%` conversion; its API is the exact frozen 020 varargs signature. General printf behavior is outside this selection. Use the actual 011 prototype, 012 opaque reference/vector/array graph, 013 native closure, 014 weak reference, 015 byte-string, 016 native creation/shared getter, 017 script closure and the required frozen 020 error/scratch production providers. Never link their legacy structural substitutes or fixture translation units as production.

The caller supplies successful aligned allocation/reallocation and disposal services, Execute, class-instance creation, native type-error formatting and the array failure endpoint. Execute `0x0018d65c`, class creation `0x00198418` and type-error `0x001a1010` are explicitly typed external contracts in this qualification. Their fixture outcomes are authored service models; their original game bodies are not replaced by cached results or reported recovered. Literal overflow/arity errors compose actual original `0x0019813c`/scratch/string execution against actual authored 020/015 providers. Reference-only SDK formatting instructions are individually hash-bound by frozen 020 evidence. General formatting and its other error branches remain unqualified.

`lookup_call_adapter.c` provides the exact 020 invoke ABI. Provision an actual complete `SqVmCallStorage022` whose first member is the exact named common 020 VM; a standalone 020 object is too small for this provider. Provision an actual `SqLookupSharedStorage020` for scratch suffix access. VM/current-frame pointer carriers are copied through bytes. On ARM the VM/frame sizes are 148/48, and frame closure is at offset 8. On the native 64-bit layouts these are 192/72 and offset 16. The native closure callable is invoked through its existing exact `I32(void *)` type, with true native pointers and no incompatible function-pointer cast.

`parent_binding.c` is an experimental 018 adapter. It reads the complete frame type and avoids the older native closure-offset-8 assumption. Its full 018 controller composition is not qualified by this packet; do not select it as a replacement provider on the strength of these call tests alone. The frozen 018 implementation is unchanged.

## Qualified observations and limits

The corpus exercises actual native registration, 0/1/2 captured owners, stack/frame growth, original array execution, final native-constructor ownership, return zero/positive/failure/`-666` suspension, live and invalidated weak environments, final old receiver destruction, positive/negative/INT_MIN arity, type-mask wildcard/pass/bound/mismatch, depth 99/100, finite float lengths, and raw noncanonical 32-bit raise-error flags across the Execute/class contracts. It compares every initialized byte of the 256 KiB owned ARM arena, callback observations and separately derived ownership/ABI models. Windows executes a real compiled PE with native pointers. Android uses compiled AArch64 objects in an explicitly labeled object model; no physical Android/AYN Thor result is claimed.

NativeCall copies inactive instruction/literal/target/root bytes from its local frame. Original dead CPU stack seeds demonstrate these 16 bytes are indeterminate. Authored C initializes them deterministically. Whole-arena byte equality therefore requires the explicit initialized-dead-stack input profile. The separate varied-seed experiment compares semantic state and excludes raw inactive-frame/debug/asynchronous observers; it is not universal machine-state equality. Real array/native handlers do not read those inactive fields in this corpus.

The original FPU context must be enabled. Callee-saved VFP registers and mandatory AAPCS control fields are checked separately. Finite length `5.5` produces sticky FPSCR IXC (`0x10`), recorded per input. Universal exception-status equality or arbitrary callee inspection is not inferred. Native Windows/AArch64 floating controls are checked under their fixture domains.

Admitted storage has valid initialized stack/frame vectors with spare registration space, bounded nonnegative indices/counts, nonoverflow sizes, successful nonaliasing aligned reallocation, and ordinary nonwrapping ownership. Result storage remains independently live across stack growth. Tested callbacks follow the declared stack/result and disposal contracts; arbitrary reentrant vector/VM mutation, GC, allocation failure, malformed object graphs, out-of-range float conversion and full script execution remain outside the packet. Disposal observers retain physical arena storage to inspect logical finalization; this is not allocator recovery.

A no-constructor class path has two statically NULL local temporaries. Their refcounted cleanup instructions cannot execute under the nonaliasing class-service contract: the discarded local is never passed to that service, and the tested constructor tag must equal NULL to enter this path. Unvisited instructions are retained explicitly in the report rather than claimed executed. Other unsupported/dead domains remain listed with the measured instruction coverage.
