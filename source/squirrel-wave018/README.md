# Script-closure creation controller 018

This component reconstructs the complete measured ARM controller at `0x00196b08` as ordinary C under explicit VM and resource-provider contracts. Its original instruction extent is `[0x00196b08,0x00196f58)`, 1,104 bytes, followed by a 20-byte literal pool. The Execute CLOSURE caller is at `0x0018fe40`. The historical measurement was saved before this lane's C implementation. There is no separately identified small creation factory: construction and capture/default binding are inside this controller.

The distinct API is `sq_script_create018(void *vm, SqPrefixObject012 *destination, SqPrototype011 *function)`. Its result is Boolean. Root owns any eventual canonical name, mapping, functional admission and source credit. This packet grants none.

The closure is the unchanged named `SqScriptClosure017`: 64 bytes on the original target and 112 bytes on the natural Windows/AArch64 layouts. Its base is the exact named collectable 012, while its function is an actual compact prototype 011 with a 12-byte target prefix. Heterogeneous objects, values and callbacks use the frozen 011/012 opaque contracts. No prototype is treated as a full collectable, and no legacy vtable is reinterpreted. Native callable storage is never invoked.

`SqScriptCreationStorage018` is an exact alias of the frozen 016 storage binding. Stack is at offset 24, stack base is a signed word in reserved bytes at 52, and the current-frame pointer occupies reserved bytes at 132. Shared is at 140 on the target and 144 on native layouts. Current-frame closure binding begins at 8, with its target payload at 12. `vm_binding.c` copies reserved pointer/word/object storage through bytes. It neither casts an opaque VM to the old full CallVM nor claims the full VM or CallInfo layout. The caller must provide these explicitly reserved bindings and actual 017 parent closures.

The controller captures shared state before allocating. It initializes the measured prefix, NULL environment/function and empty vectors. It performs prototype temporary retain/assign/release before initializing shared/list links. The initial allocation callback observes only allocation arguments and the VM binding; it never reads incomplete new fields. Reallocation and other observers run after complete initialization/list publication. Reference counts remain finite without overflow, so prototype temporary disposal cannot escape into an unsupported partial-construction callback.

Outer/default counts are cached before their respective reserves. Descriptor arrays are selected each iteration. Only the low byte of the outer kind matters: 0 selects a local stack object, 1 appends NULL and calls indexed lookup, 2 selects a parent's captured value, and other low bytes skip the descriptor. Local, parent and default source pointers are selected before append growth. Subsequent iterations reload the required current storage. Default indices are signed words relative to stack base.

Publication retains a temporary owner, retains/publishes the destination, releases the previous destination, then releases the temporary. A returning previous-owner callback observes two owners and the already-published destination. It may clear that destination while the temporary keeps the new object alive until the callback returns. Indexed lookup failure instead calls the error binding and returns false without publishing the destination or releasing the raw, linked, zero-count closure. This observed failure behavior is preserved; GC cleanup of that object is outside this packet.

There are three evidence modes. Local/parent/default cases execute the original controller with explicit allocation/disposal services. Interface cases supply authored, typed lookup/error callbacks on both sides; these qualify the call/ownership contract, not the complete original VM providers. The narrow real-provider case executes actual original `0x00198578` and table Get `0x001a1dc8` for a one-bucket table, an actual interned byte-string 015 key and native-closure 013 value. The source side independently scans the declared table fixture and assigns the value. It never consumes cached original results. This scan is a test provider, not a complete table Get recovery. The exact sealed `SqTable019`/`SqTableNode019` header is reused; table construction/lifetime and broad indexed-get/error behavior are not qualified here. No original indexed-error body executes in the admitted cases.

The fixture composes actual compact prototypes, raw 8-bit strings 015, native closures 013, parent script closures 017 and weak references 014. It covers compact-prototype final-owner destruction, both prototype and created-closure weak destruction orders, source/destination aliases, lookup failure with retained writeback, unknown/high-byte kinds, empty/one/three-element captures, six-element growth, changed VM/shared storage, descriptor relocation and cached count behavior. Storage is an explicitly provisioned retained arena; callback-driven relocation keeps selected source storage and referenced payloads alive. Table receivers keep external owners and do not enter unqualified table finalization.

The string shared-state adapter remains the frozen 015 byte-copy pointer slot at 20 inside explicitly reserved opaque storage. This is not a full portable shared-state layout or proof that future adjacent fields cannot overlap it. Allocation/reallocation and disposal are typed test services; no original allocator backend, successful OOM behavior, GC, cycles, races or full VM is recovered. NULL prototype/allocation/reallocation, invalid pointers/indices, negative counts, overflow, exhausted storage and assert 146590 paths are excluded.
