# Weak-reference lazy creation and final lifetime

This component reconstructs three complete original ARM bodies: cached creation at `0x00233b7c..0x00233bd4` (88 instruction bytes and four pool bytes), release at `0x006a7780..0x006a77c0` (64 instruction bytes), and destructor at `0x006a77c0..0x006a77ec` (44 instruction bytes and eight pool bytes). The latter two are unseeded and require coordinator census review. The actual vtable at `0x008516ec` comes from the lazy constructor's literal and selects these bodies. The preceding frozen 010 pool ends at the release entry; a neighboring table witnesses the following entry `0x006a77f4`. Measured callers are `0x00741904` and `0x00743810`; the latter has an explicit reference-tag guard. The 196 measured instruction bytes are not self-admitted source or exact credit.

`SqWeakReference014` is exactly the frozen named `SqPrototypeWeak011` type: a noncollectable prefix followed by a tagged, nonowning target. Target size is 20 bytes, prefix 12, tagged target 12 and pointer 16. Native size is 40, prefix 24, tagged target 24 and pointer 32. The actual prototype's 12-byte prefix and the genuine named native-closure collectable's 20-byte base remain distinct. Every common prefix is the exact frozen 011 type; collectable ownership uses frozen 012's named type through unchanged 013. Nothing casts prototypes or weak objects to full collectables or reinterprets legacy `SqRef` vtables.

Creation returns the existing cache unchanged, without allocating, retaining the weak object, retaining its target, or refreshing its tag. On a cold cache, it requests one weak allocation, publishes the returned block, initializes references/own weak link/vtable, and sets the tagged target. The allocation service observes the old cache before publication. Its callback may temporarily replace that cache; the returned allocation is subsequently published. Successful aligned nonoverlapping allocation is an explicit service contract, not allocator reconstruction. Tests poison the returned storage to verify constructor initialization rather than relying on zero-filled memory.

Final weak release clears the current reference-tagged target's backlink before calling its current virtual destructor. It does not decrement or finalize that target. The destructor installs base identity and invalidates the target of its own attached weak reference. Disposal happens afterward with the weak allocation size. This supports both weak-first and owner-first destruction, plus weak-of-weak chains. Cached/retained pointers are not silently cleared when the original leaves them intact.

The original NULL-allocation path is measured separately: it publishes NULL, skips initialization, and attempts a four-byte target-tag write at address 12 from `0x00233bc0`. The original-only probe substitutes an authored allocator that returns NULL and records the invalid access without changing original instructions. The source NULL path is not executed or admitted; C undefined behavior and recovery from allocation failure receive no equivalence claim. Generic ref-tagged targets must point to live, valid named prefixes. Unsigned count edges and a nonreference-tagged owner-address payload are explicitly machine-word edge fixtures, not valid ownership proofs.

The fixture composes the unchanged actual prototype 011 and native-closure 013 finalizers with the new weak family. Those finalizers have separate frozen contracts and receive zero duplicate credit. Prototype 011 disposal normalization uses only the fixture's empty compact prototype; native 013 uses its measured full type and explicit disposal provider. Its stored `I32(void*)` callable carrier remains uninvoked and does not qualify the older CallNative ABI. All vtable callbacks use the exact frozen `void (*)(void *)` type with actual receiver adapters. A wider legacy graph requires explicit typed dispatch or coordinated type migration.

The foreign allocation/disposal services are ordinary C and retain storage for inspection. The weak APIs are guarded against reading beyond either real owner's actual 12-byte prefix and against reading a logically disposed owner after invalidation. Fixture observations may inspect retained owner storage after logical disposal. These tests do not establish physical allocator behavior. Extra virtual-destructor cases are declared callback-interference controls, with normally returning callbacks that preserve current control storage. They do not assert that arbitrary malformed ownership graphs are valid game states.

The durable producer `toolscripts/squirrel_weak_reference014.py` verifies frozen 011/012/013 identities, builds ordinary source ARM, actual Windows, and actual Android AArch64 objects, then compares 72 cases against original execution. All 49 new original instruction addresses are visited. ARM compares the normalized 64 KiB foreign heap; all platforms compare typed owner/weak fields and ordered allocation/destruction/disposal observations. Android objects execute above 4 GiB in a Cortex-A72 model with saved integer, x18, floating-point and stack checks. A shared-library 16 KiB maximum-page link is not an APK/Android OS, physical device, AYN Thor or game execution claim.

Twelve public Windows tests require no original inputs. Eight independently compiled wrong-C controls return normally on ARM and Windows and are rejected. Four retain the same final heap: detachment after virtual destruction, invalidation after disposal, and wrong allocation/disposal size requests. Other controls allocate despite a cache, refresh a cached tag, retain the nonowning target or ignore its reference flag. The allocator/disposal callbacks make those same-heap ordering/request differences observable before the eventual final state.

The preserved unmodified Squirrel 2.2.5 `source/squirrel-wave001/upstream/squirrel/sqobject.cpp` was a semantic reference. Archive identity and the zlib-style license remain in the frozen upstream manifest/COPYRIGHT. The actual fork identity is unclaimed; addresses, layout and order come from this owner module. New source is authored reconstruction. Original payloads, raw instructions/disassembly, binaries and private logs remain ignored. GC, arbitrary cycles/races, constructor families of target objects, allocator recovery, native-call execution, whole VM/game and physical-device behavior remain outside scope. Previous packets and shared registries/census remain unchanged.
