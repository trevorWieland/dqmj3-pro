## Frame lifetime and equivalence

The original local native CallInfo does not initialize its instruction pointer, literal pointer, target or root fields. It copies those four 32-bit words from dead stack into a native frame, then clears the frame's owned closure and pops it. The actual array handler reads only stack/top/base/shared fields; the explicit native observer consumes the active frame's closure, previous base/top and call count. Memory-read tracing verifies neither admitted handler reads the four indeterminate fields. The central path invokes no debug hook. Arbitrary raw-frame/debug observers, reentrant destructors and handlers that inspect these words are outside this proof.

The portable C initializes every frame field deterministically. Each original and source run separately checks every byte of the randomized declared heap against its own independent model, including the original dead-stack-derived words and the source's zeros. Source/original semantic-state comparison then excludes only those 16 explicitly identified bytes in the newly used frame. It additionally rejects any raw difference elsewhere. Four executions hold heap/input constant and vary only the original dead-stack seed: original raw hashes change, source raw hashes stay constant, semantic hashes remain identical, and the handlers read none of these fields. Byte-for-byte whole-memory equality is deliberately not claimed.
