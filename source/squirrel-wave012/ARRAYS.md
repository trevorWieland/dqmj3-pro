# Opaque array lifetime successor

This component supplies one named array using the exact opaque 011/012 reference, collectable, shared-state and value-vector contracts. Its target layout is 36 bytes with values at 24; the native layout is 64 bytes. It preserves the original array factory 0x665a44, release 0x665bd4 and destructor 0x665c60 semantics with distinct portable API names. Frozen 002/007 code and all earlier 012 packets remain unchanged, and receive no duplicate byte credit.

Production uses `array_reference.c`, `array_vtables.c`, opaque core `reference_prefix.c`, `vector_values.c` and `reference_dispatch_opaque.c`, plus the actual frozen lifetime families required by payloads. Supply the declared allocation/disposal services and ordinary compiler runtime. Select opaque callback tables consistently. A legacy ARRAY dispatcher must never be combined with these tables: its superficially similar callback representation has incompatible function types.

The fixture composes the new array with the frozen mixed native/prototype DAG, using that fixture read-only. Test-only compilation renames its disposal exports so the new observer can route every disposal while preserving the frozen checks. This does not modify an engine provider or supply original implementation code. The array owns a real native closure, compact prototype and nested child native closure. Actual weak 014 references are released before or after the array; current weak-target and owner-cache observations remain explicit.

The corpus covers requested sizes 0/1/2/4/9, all four frozen DAG variants, both weak orders or no weak, and successful or null array-object allocation. Null object allocation safely returns null in the original array factory. Vector allocation must succeed with valid aligned nonoverflow storage; null-vector failure recovery is not claimed. Ordinary final-owner release uses unmarked arrays. GC collection, arbitrary reentrant observers and complete VM wiring remain outside this packet.

Original and authored ARM execute their complete selected source/original closures and compare every owned heap byte without masks or vtable normalization. Windows uses real host 64 named objects; compiled Android AArch64 source-object execution places heap pointers above 4 GiB and checks its integer/platform/SIMD control contract. This is not physical Android or game execution. Logical disposal retains physical memory until snapshots, so stale representations after logical free are observations rather than live weak references.

Returning controls deliberately free the array before destruction, omit GC unlinking, or clear its weak target before child/vector disposal. Premature free and weak reset can reach the same final heap while changing observable disposal state. Names and string providers remain absent. All fixtures, Windows-only `native_array_fixture.c` and absolute-original-entry test shims are excluded from production.

Run `python toolscripts/squirrel_reference_array012.py --output work/squirrel-reference-prefix012/qualified-array`, then its copied-source replay. Coordinator review is required. New canonical-byte, exact, duplicate, whole-VM and game credit are zero.
