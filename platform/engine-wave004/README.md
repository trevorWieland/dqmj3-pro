# Atomic measured material views

This packet closes the four picture-material cases excluded by wave003 and separates private parser staging from every published scene value. It handles all seventeen picture bindings in the owner's actual NaviMap layout. The same measured static map is mirrored into the two platform views to exercise resource ownership, viewport fitting, display lifecycle and input routing. This is not the game's upper scene, gameplay, a source-only game or an emulator wrapper. New recovered game-source credit is zero.

The owner's base SARC identity remains a56be941dd4e8b4f71abd12141efd47916ebcf50174379cc86735fd78b8a5099. The update's RomFS inventory has no replacement at that path. The measurement script rehashes the owner CIA and extracts the selected SARC into this packet's private work directory. Ten textures, 277,465 logical pixels, thirty-five panes and seventeen pictures are bound to those original identities. Two texture-free font materials, eighteen non-picture panes and the animation remain outside picture rendering. The 128 encoded image-storage bytes not addressed by the logical/padded texels remain counted and uninterpreted.

## Atomic ownership

The frozen pane implementation is compiled with a private staging_layout_ namespace. The stage owns its parser state, texture arena and temporary rasterization buffers. The component copies a fully accepted candidate's geometry, frame and statistics into an inactive, separately allocated publication bank, then changes the current bank once. Both view APIs read that same committed bank and generation. Production libraries expose no staging API. The test DLL exports a read-only stage observer solely to prove the negative case is not vacuous.

The late-failure control first changes valid pane geometry and replacement texture data, then supplies a nonfinite material transform. Tests observe the changed private geometry while every old published geometry value, statistic, frame and input state remains unchanged across both views. Unknown picture-material operations also reject the whole candidate. A resource request's failure status may change; it cannot publish a partial scene.

The resource queue and its two already accepted recovered stack functions are reused from frozen wave002. Newest requested scene imports own publication. Pause cancels pending jobs and clears input; late completions cannot replace either view. Secondary-surface generation checks reject stale closes, surface replacement releases held input, only the primary owns the update clock, and bottom-view touch coordinates map to measured picture geometry. Geometric picking and recorded controller state are platform diagnostics, not recovered game actions.

## Material evidence and implementation

Older format documentation leaves the detailed material extension unexplained. Current external Cafe readers also interpret this version's extended flags differently. Original update code resolves the measured layout:

- The constructor's bounded arithmetic at 0x00554b00–0x00554c9c establishes a 28-byte detailed header gated by bit 19, followed by twelve-byte detailed stages counted by bits 20–22, after projection data. All nineteen original material records are checked. This prefix is not a complete constructor reconstruction.
- The original texture-matrix function at 0x0055492c returns for all owner transform profiles and thirty-two synthetic rotation-study cases. Its console texture Y inversion is explicit. Owner transforms have zero rotation; nonuniform images with nonzero material rotation remain outside this renderer's accepted profile. The original trigonometry's small approximation difference is recorded separately and is not treated as exact.
- The original pane-projection function at 0x0054befc executes its actual inverse and matrix-multiply dependencies. Synthetic translations, scales and texture dimensions confirm pane-based source 4 with adjustment flag 4 and an identity draw-info matrix. Projection follows pane-local position in texture-pixel units.
- The original GPU-command emitter at 0x0054df04 executes without external-call stubs. Captured PICA registers establish the measured detailed RGB replacement, texture-alpha modulation, selected constant and source-over blend. The detailed path bypasses ordinary automatic black/white color remapping. Altering the original alpha operation changes the emitted commands. Original command bytes stay private; public evidence contains their hash and decoded semantic claims.

The formerly excluded nonidentity/repeat picture uses a verified uniform texture. Sampling a constant image is invariant under its supported wrap/transform profile, so this case closes by an exact reduction. The two projected picture cases use the original-qualified pane projection. The two-texture detailed case executes its explicit replace/modulate equations; its measured uniformly zero alpha mask produces a transparent contribution. It is a processed picture case, not silently skipped.

The C sampler now provides linear filtering and edge/repeat addressing for the measured profiles. Default single-texture materials retain their color remap and vertex/leaf alpha; detailed materials follow explicit TEV inputs instead. Native tests distinguish zero-mask behavior from the incorrect automatic-black-alpha remap and verify constant modulation, replacement controls, projected texture-unit repetition and neighboring-texel interpolation.

This is a bounded material profile. Other mapping sources, projection flags, detailed operators, primitive-color sources, unknown extended fields, nondefault detailed vertex/leaf alpha and ambiguous mixed filtering of a nonuniform image reject publication. The renderer does not claim bit-identical PICA fixed-point filtering, original game draw-info state, animation, font rendering, part expansion or original hardware pixel equivalence.

## Platform execution

The native Windows program loads the extracted archive through the recovered resource queue, renders both integration views into a real GDI surface and verifies all 192,000 RGB pixels, including letterboxes. A second execution changes private pane data before a late material failure and checks both geometry and pixels remain published from the old scene. The public executable's missing-private-asset path is also executed. Its resizeable interactive window, keyboard and bottom-view mouse routing compile; interactive GUI execution is not claimed.

The Android app is org.dqm.materials, arm64-v8a, minimum API 29 and target API 36. It imports a selected extracted archive with the system document picker, validates on the serial UI owner, writes successful inputs through app-private AtomicFile, and sends stale callbacks through cancellation cleanup. Surface callbacks and dynamic Presentation display enumeration choose roles without fixed display IDs. Both views use the same committed generation, with stacked fallback on a single display. Gamepad buttons, joystick axes, touch identity, pause, surface loss and configuration changes connect to the native service. The static map in both views is labeled as integration content.

The development APK contains no original assets or original executable image. Its signature, JNI closure, uncompressed native-library identity and 16 KiB ELF/ZIP alignment are verified. The isolated ADB probe uses port 5044 and its own home directory. No Android device is attached; installation, Android surface/document-provider behavior, dual-display hardware, controller hardware, 16 KiB device execution and AYN Thor execution remain untested.
