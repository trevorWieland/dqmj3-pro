# Wave 002 typed record-access family

The exclusive claim contains 257 distinct physical ARM functions, each 12 bytes: read a record pointer from an aligned field of the input handle, load a scalar field of that record, and return through LR. The scalar loads cover unsigned words, unsigned bytes/halfwords, and signed bytes/halfwords. The source expresses these as ordinary typed structure-member access, with explicit signed primitive types and compiler-checked field offsets.

The records are partial structural views. `field_XXXX` means only the observed scalar at byte offset XXXX. `unknown_XXXX` preserves unclassified space and earns no data/source credit. Neither a field's gameplay meaning nor the original class name, record extent, lifetime, ownership or allocation protocol has been recovered by this packet.

Nearby functions with the same handle-pointer offset and scalar load type share a view declaration. The address-page token is a source-organization cohort, not a claim that every function in that cohort belonged to one historical class. Typed views of different widths remain separate, avoiding invented overlapping field declarations or an artificial union of unrelated types. Existing wave 001 sources and all its claimed intervals are excluded.

The ARM32 handle offset is asserted only when pointers are four bytes. Native 64-bit C objects may place their pointer field differently because of pointer size/alignment. Those host objects must be created using their host type layout; a raw ARM32 pointer graph cannot be read as an x64/ARM64 C object. Binary asset/address adaptation and new host memory fixtures remain separate portability work.

Each claimed body is checked against the pinned update executable, an independent single-range Ghidra function boundary, three fully decoded unconditional ARM instructions, and an actual direct call or tail branch contained in a Ghidra caller body. An ARM B/BL word scan over the initialized text rejects direct interior targets. This does not establish the global absence of indirect interior entries.

The validation script consumes frozen source and header files. It does not regenerate accepted C from machine instructions or alter compiler outputs. Every complete function section must equal all 12 original bytes and have no body relocations. LLD then places those actual compiled sections at their original addresses in a source-linked ELF. Its unowned address gaps and discarded unwind metadata receive no source credit. Complete module integration belongs to the coordinator.

The independent memory model initializes deterministic root, record and stack regions, installs a record pointer and typed field bytes, and computes the signed/unsigned result directly from those bytes. Each original and source execution starts in a fresh ARM1176 Unicorn machine. Two pointer geometries and 12 edge/pattern values provide 24 fixtures per function. Runs require an actual return within 16 instructions and 100,000 microseconds, exact ordered read addresses and widths, no stores, preserved callee-saved registers/SP/LR, unchanged memory and agreement of original/source architectural observations. Every owned instruction address must execute.

A separately compiled wrong C implementation flips the returned field's low bit. Each wrong body is genuinely linked at its own private test address, actually returns, and must disagree with the independent model. Its instructions are never substituted into an accepted object or counted as reconstructed source. Unmapped handle/record controls must fault with zero return credit. Supported aligned valid-pointer fixtures are distinct from those unsupported-pointer rejections.

The resulting packet is a proposal for coordinator review. Exact standalone spans, bounded fixtures, caller/boundary evidence and compiled controls do not themselves publish accepted coverage or prove a complete game/platform build.
