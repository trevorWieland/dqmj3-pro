# SLEIGH/P-code range-function audit

This research pilot establishes the declared range-function contract through a second machine-semantics path and two local SMT solvers. It grants zero source credit and changes no admission policy. The normal game C, prior formal pilot and inventory/native packets remain unchanged.

The actual original 20-byte ARM body at `0x0069180c` comes from the hash-bound owner update module. The unchanged ordinary C function is compiled and genuinely linked again at that VA using the measured public Clang profile. Its complete linked bytes still differ from the original. The wrong-bound C is separately compiled and linked. Every whole object/linked span, source, ELF, dependency and relocation check is recorded; no instruction or encoding is patched.

## Results and independent paths

Eight audit queries return UNSAT in both Z3 5.3.3.0 and cvc5 1.4.2: original P-code against the typed C contract; compiled P-code against that contract; wrong-source P-code against its own typed contract; complete path coverage for all three bodies; the typed C expression against the manual inclusive range; and original versus normal compiled P-code observations. ARM and Thumb caller-return domains each have SAT witnesses, and the domain contains no restriction on R0 or initial NZCV. The argument domain covers all 2^32 unsigned-int32 values, not a fixture sample.

Both solvers find input 11 for the genuinely compiled wrong source. Actual original execution returns 0 and wrong-source execution returns 1 after reaching the return sentinel, for all sixteen initial NZCV patterns and both return modes: 32 reproductions. There are 480 concrete input/flag/return configurations and 1,440 actual executions across original, normal and wrong bodies. P-code agrees with every observed core-register result, architectural arithmetic flag, return target and instruction-set mode. Fixtures include signed-boundary bit patterns, random words, ARM continuation offsets 0/4 and Thumb continuation offsets 0/2. Data reads/writes are absent; callee-saved registers, SP, LR, mapped data bytes and other CPSR bits are preserved.

cvc5 also replays all five frozen prior-pilot SMT files as UNSAT. The new binary-semantics path does not import or call the prior handwritten ARM instruction translator. It obtains raw P-code directly from the measured Ghidra SLEIGH decoder and uses a new generic P-code interpreter. The prior Clang typed-C contract whitelist remains shared and explicitly trusted. Agreement between two solvers checks the same formula; it does not independently establish the correctness of either shared translation or frontend. The exact cvc5 release, wheel, Python extension and bundled DLLs are pinned, and all effective package files are compared against that wheel. [cvc5 public release](https://pypi.org/project/cvc5/1.4.2/), [public solver source](https://github.com/cvc5/cvc5)

## Raw P-code and the mode bridge

Fresh private raw imports use `ARM:LE:32:v6`, with no automatic analysis or decompiler simplification. Ghidra exports the actual complete original and linked bodies, every P-code operation/typed varnode, register descriptors and effective context values. The original yields 65 operations and four symbolic paths; each compiled body yields 60 operations and two paths. The interpreter implements only the sixteen measured generic integer, Boolean, copy, subpiece, conditional-branch, user-operation and return operators. Conditional branches must target later owned instructions. Relative/backward/escaping flow, loops, LOAD/STORE, direct RAM operands, unknown operators and uninitialized temporaries fail closed. Every path must reach the actual terminal RETURN. [Ghidra operation reference](https://ghidra.re/ghidra_docs/languages/html/pcodedescription.html)

The only supported user operation is the measured `setISAMode`, ID 62, with exactly one canonical byte argument TB and no output. Its explicit assumed effect is to copy TB to runtime/decoder Thumb mode, with no other register or data-memory effects. Canonical 0/1 values are established structurally from constants and generic Boolean-result ITEs. The actual SLEIGH branch sequence computes TB from LR's low bit and masks the return PC; the interpreter does not reimplement the ARM BX instruction. This one context bridge remains a trusted assumption despite concrete qualification. [Public ARM SLEIGH source](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/ARM/data/languages/ARM.sinc)

The pinned installed `ARM_v45.cspec` contains a decompiler no-op fixup for this user operation. This audit uses the earlier raw instruction P-code, where the operation remains present. Dropping the mode effect produces a SAT contract failure in the regression tests. Other user operations are rejected rather than treated as no-ops. [Public compiler-specification source](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/ARM/data/languages/ARM_v45.cspec)

The exporter explicitly sets TMode, LRset, REToverride, CALLoverride, TEEMode and itmode to zero before disassembly and records them at every instruction. This selects callable ARM code with no LR-setting prefix, analysis call/return override, ThumbEE or IT block. LRset/override fields are decoder annotations, not extra architectural arguments. Other effective values, including unknown values, remain visible in the private export. No theorem is claimed for arbitrary Ghidra override configurations. A recorded comparison confirms the explicitly qualified contexts produce the same operation sequences as the earlier default-context feasibility export.

## Contract, defined C and limits

The contract starts in user-mode ARM state with canonical arbitrary NZCV, an aligned SP and a valid mapped executable caller LR outside the owned body. R0 is the scalar result. R4-R11, including platform R9, SP, LR, all data memory and CPSR bits other than NZCV/T are preserved. The return target and mode must follow LR. R1-R3, R12 and final NZCV are caller-clobber observations. Existing machine callers using additional private register/flag guarantees are outside this AAPCS contract and need separate review before any replacement claim. [AAPCS32](https://github.com/ARM-software/abi-aa/blob/main/aapcs32/aapcs32.rst)

The shared source-language gate checks the actual typed AST of `x >= 1u && x <= 10u`, including the conversion of int 0/1 to unsigned. Target macros and C11 static assertions establish the 32-bit unsigned value domain. Both comparisons and both pure logical operands are defined for every input. There is no arithmetic overflow, invalid shift, division, pointer validity, uninitialized read or sequencing restriction in this expression. This source-language argument is separate from compiled-byte equivalence; it is not a verified full-C frontend.

Ghidra/SLEIGH, the raw exporter, generic P-code-to-SMT interpreter, explicit mode bridge, shared Clang frontend/contract, SMT serialization, both solvers, Python, host and files remain trusted. Concrete Unicorn qualification is an additional check, not a universal proof. There are no independently checked proof certificates. Exceptions, interrupts, concurrency, timing, caches, MMU behavior, general memory operations, calls, loops and complete game execution remain outside the model. The audit does not promise full ISA or C-language support.

## Reproduction and retained attempts

Run `tools/python/Scripts/python.exe toolscripts/formal_audit_wave002.py` or the targeted `-m unittest discover -s tests -p test_formal_audit_wave002.py -v`. Each invocation creates a new owned run and exports fresh P-code. Public cvc5 1.4.2 is installed only in the existing project-local environment, from the cached Windows CPython313 wheel whose SHA256 is `0ee0a51862d9e8ae8a38572909641a88cdf8d5e1640dee481b24289b6811b9da`. No shared tool lock, global Java state or source registry is changed.

Prerequisites include the canonical generated code, measured Clang/LLD, qualified read-only Ghidra, local copied JDK and frozen prior pilot inputs. For the additional prior-query audit included in this packet, each exact prior query must exist in this checkout or the original owner checkout named by the frozen pilot receipt; it is hash-checked and copied into the new owned run. Missing inputs fail completeness rather than being skipped. Raw code, P-code, ASTs, queries, ELFs, execution traces and caches stay private under work.

Two failed attempts are retained. cvc5 first rejected a duplicate set-logic directive; the parser setup was corrected. A conservative canonical-byte check then required the simplifier alone to discharge a valid Boolean ITE and rejected it; a sound structural check replaced that guard, with explicit rejection tests for noncanonical bytes. Neither failure published a new completed audit packet. Earlier complete feasibility outputs and all staged source/tool artifacts remain available for comparison.
