# Native wave 003: typed field setters

This lane proposes **58 functions and 696 instruction bytes** for independent coordinator review. Another three matching functions, totaling 24 bytes, remain unaccepted because their indirect member-call target bindings have not been independently proven. All 61 functions have complete object and genuine source-linked spans identical to the frozen update executable. Exact diagnostic bytes and proposed source credit are separate.

The authored `setters.c` contains ordinary void functions assigning a 32-bit argument to typed byte, halfword or word fields. `views.h` declares partial record and handle views with unknown prefixes and fields named by measured offsets. These are provisional views of observed memory layout, not recovered original class names or claims about gameplay meaning. There is no assembly, executable blob, instruction/register transcription, compiler-output modification or forced instruction encoding.

The compiler configuration is the public local Clang 21 toolchain targeting ARM MPCore in ARM mode at `-O2`, with function sections. All 61 exact object functions were individually linked by LLD at their original virtual addresses. Complete symbol bytes, hashes, section names, source/header/object/ELF hashes, body relocations, unresolved-symbol checks, tool/runtime identities and reproduction argv are in `packet.json`. This matching configuration does not identify the historical compiler.

Each function passed 61 edge and seeded-random value/fixture trials, for 3,721 original/reference cases. The original and source-linked functions were separately executed. The independent model checks all bytes of the handle, record and stack snapshots after return, correct truncation for byte/halfword stores, exactly the declared pointer reads and field write, callee-saved registers, SP and LR, return to the sentinel, and instruction execution restricted to the complete function span. Handle/record base offsets and initial registers, flags and unrelated memory vary across fixtures.

For every function, a compiled wrong-value source and a compiled wrong-field-layout source also executed. Each returned to the sentinel and then raised the specific `MemoryMismatch` exception, with actual/expected bytes and snapshot hashes recorded. An arbitrary exception does not satisfy these controls. Two additional controls required the precise `UC_ERR_WRITE_UNMAPPED` and `UC_ERR_WRITE_PROT` failures, giving 124 successful negative controls in total.

`claim.json` freezes exclusive intervals and semantic field models, excluding earlier source waves. `boundary.json` binds single-range Ghidra extents to independently decoded direct ARM calls for the 58 proposed functions. Full original instruction spans have no literal pools or body relocations. Private neighboring disassembly and call context are under `work/wave003-native/contexts.txt`; only hashes and metadata are published here.

The three unaccepted entries are `0x0055a368`, `0x0055a370` and `0x0055a558`. Ghidra lists indirect member-call edges to them, and their aligned addresses occur in read-only pointer-table entries at `0x00807c80`, `0x00807c88` and `0x00807c90`. Their exact C and bounded write behavior are retained diagnostically, but this does not prove the dynamic target binding or source interface. `directCallerQualified` is false for these entries. The initial direct-call assumption failed closed and its log is preserved in the review summary.

Reproduce the packet from any working directory using the repository's `tools/python/Scripts/python.exe` and the absolute `toolscripts/native_wave003.py` path. Source, header, claim, original module, Ghidra catalogue and tool hashes are checked or pinned. Generated objects, linked ELF files, negative sources and logs remain under `work/wave003-native/`. `review-summary.json` gives the frozen packet identity and proposed/unaccepted split.

These are bounded mapped-RAM behavior checks under the measured ARM ABI, not universal equivalence or platform/game execution. The partial structures target the observed 32-bit pointer layout; Windows/Android source ports need explicit adapters and eventually unified recovered types. Coordinator integration, clean replay and accepted-source accounting remain separate steps.
