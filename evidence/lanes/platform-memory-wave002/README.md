# Stable-input host64 memory component replay

This replaces the input-closure policy of the frozen memory-wave001 lane. It compiles the same unchanged 257 getter and 58 ABI-qualified setter definitions. Copied platform harness code and generated test glue add zero recovered-source credit. The old lane's source, inputs, corpus and receipts are unchanged.

The failure addressed here was a raw hash dependency on native lane runtime packet JSON. Reproducing those packets in a fresh checkout changes absolute object, executable and output paths, even when their canonical source and function identities stay identical. A runtime packet is therefore a result of replay, not a stable source dependency.

`platform/memory-wave002/inputs.json` pins source, headers, pure native oracle helpers, getter layouts, immutable bundle001 acceptance, immutable qualified setter boundaries, and `functions.json`. It explicitly forbids runtime `packet.json` inputs. The function descriptor binds each canonical build/program/module/hash/address/ARM identity to the source/header hashes and typed partial layout. It contains no object, executable or runtime-output paths.

The loader independently checks all 315 complete original instruction spans. It decodes their pointer load, scalar load/store width and signedness, field offset and unconditional return. Getter identities also match immutable parent acceptance and semantic layouts. Setter extents match their qualified boundary descriptors, and their original direct caller words are decoded again. Missing functions, duplicate identities, changed source/tool pins and relabeled layouts fail before platform compilation.

Every build captures a fresh 7,560-case corpus from the immutable original ARM module: 12 scalar boundaries/patterns and two cases per function. Frozen getter and pointer-return setter oracles verify actual returns, ABI/state/read-write contracts and an independent model. The portable observation is the getter scalar or the setter's truncated field plus captured logical record return. Absolute ARM virtual addresses are not equated with host pointers.

Windows executes the unchanged production C using real eight-byte pointers and typed host objects in two aligned geometries. Full handle and record allocations are compared, including neighboring elements and padding. The 58 setter return-pointer checks cover 1,392 invocations. Separately compiled wrong getters and setters all return before semantic rejection; wrong setters fail 1,392 memory comparisons while preserving their logical record return.

The same production source builds as Android API-29 AArch64 PIE and shared-library artifacts. Inspection requires all 315 shared-library definitions, the Android linker path and at least 16 KiB alignment in every load segment. This is cross-compilation and ELF evidence, not device execution, an APK or a game build.

The full project tool closure includes Clang/LLD and dependent DLLs, Bionic link inputs, the venv launcher, Capstone, Unicorn, pyelftools, native libraries, METADATA/WHEEL and the three installation wheel archives. Raw installer RECORD files are excluded because installation paths change their contents. Venv configuration is validated structurally: system packages disabled, exact version, runtime home matching pinned CPython, and the creator executable qualifying through pinned base/launcher hashes. Only its diagnostic creation command is ignored. `runtime.json` additionally pins the installed CPython base binaries, native extensions, standard-library source and bundled ensurepip wheel. This same-host clean-root qualification still requires that explicitly pinned installed CPython base; it does not claim machine-independent Python distribution packaging. Reported native library versions remain separate from package metadata versions.

The isolated replay copies declared inputs, compiler/link inputs, immutable wheels, the unchanged original module and this lane's harness into a new root beneath its owned work directory. It creates a fresh venv and pip-installs all three pinned distributions offline. All 130 effective tool pins and structural venv constraints must pass before execution. It materializes native lane runtime JSON with different absolute output paths. The original input manifest and descriptor are copied byte for byte; no pin is refreshed. The fresh corpus must be byte-identical to the main-root corpus, and Windows positive/wrong execution plus Android checks run again. Old work artifacts and original runtime outputs are absent from the minimal root.

Twelve unittest cases retain all eight earlier meaningful checks and add stable-packet rejection, canonical identity/span/layout corruption controls, structural venv controls and the complete fresh-venv isolated-root replay. The first attempt exposed Windows spawn pickling of an importlib-only module name before capture. The producer now resolves and verifies its canonical local worker module.

The first isolated replay also exposed a separate inherited path bug: negative-source mutation selected getters by searching an absolute source path for `wave002`. That ancestor name also appeared above the isolated setters, so only 6,168 getter controls were mutated although all 7,560 functions returned. Canonical per-source kind descriptors now select the mutation, each declared body must change, and every negative fixture must disagree after returning. Both failed attempts remain private; neither was promoted as successful isolated qualification.

Coordinator preflight then found that the first passing v2 replay copied its venv and therefore missed fresh-install differences in pyelftools RECORD and pyvenv.cfg. That ready manifest and all its files are preserved under the private `prior-copied-venv-proof/` directory. The current manifest removes installer-dependent hashes without changing effective code/native-library/standard-library hashes. It passes preflight against the independently installed cold 522c venv and uses a newly created offline-installed venv in the supported test.

The legacy `--capture-native` flag is accepted for pipeline compatibility; this producer always captures fresh original fixtures. `--output` selects an owned work root. Default artifacts retain the `report.json` and `corpus.json` names under the new evidence lane so a coordinator can switch the pipeline without modifying historical evidence. The isolated receipt records the changed runtime JSON hashes and unchanged manifest hash.

The three unqualified indirect setter diagnostics remain excluded. This lane changes no game logic, native source acceptance or denominator. Its bounded component results do not establish universal equivalence, aliasing outside the declared disjoint-object domain, a complete engine, a source-only game, Windows game execution or Android game execution.
