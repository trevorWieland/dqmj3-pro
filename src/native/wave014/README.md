## ABI and storage

The original indexed sine/cosine takes two ordinary pointer arguments in R0/R1 and its floating argument in S0. Its declaration uses Clang's documented [`pcs("aapcs-vfp")`](https://clang.llvm.org/docs/AttributeReference.html#pcs) on ARM, and the native platform convention elsewhere. The other entries take typed pointers through their ordinary platform ABI. No source routine interprets a register file or executes original instructions.

Draw view and viewport-pointer offsets are 116 and 176. Pane width/height are at 60/64 and its world matrix is at 72. Material storage uses the frozen constructor's real capacity fields and platform pointer width, including 8-byte ARM32 versus 12-byte packed native generators. The material/header types use four-byte packing. All float objects and escaped float pointers require at least four-byte alignment; there are no escaped pointers to underaligned eight-byte scalar members. The native tests use foreign storage above four GiB aligned to four but not eight bytes. Callers must provide compatible typed or foreign allocated storage; incompatible effective-type aliases are outside the contract.

Matrix outputs may overlap either input, including a four-byte partial overlap. The inverse returns zero and preserves the output when its rounded determinant is zero. SRT input/output storage must be disjoint. Sine/cosine output pointers may coincide, with the final cosine store winning.

## Numerical contract

Qualification uses IEEE binary32, round-to-nearest with gradual underflow, masked exceptions, and disabled contraction. The C preserves multiplication/addition order, including translation-first matrix accumulation and the inverse's expanded determinant. Floating exception flags and errno are not qualified observable outputs.

Indexed-angle input may be any **finite** binary32 value, including subnormals and both signed zeros. The finite power-of-two remainder specialization avoids an unsafe out-of-range float-to-integer conversion: magnitudes below 2²³ cast only in their bounded range; exponents 23–38 use an unsigned significand with shifts 0–15; exponents at least 39 are integral multiples of 65,536 and reduce to zero. The final cast is always of a nonnegative value below 65,536. Negative sine is applied only for an input strictly below zero, matching the original signed-zero behavior.

The original generic modulus wrapper and core execute in the large-angle oracle. They are not recovered or credited here: the source substitutes the finite, fixed-divisor mathematical operation. **NaN and infinity are not admitted**, and original nonfinite error/TLS/errno paths are not claimed. The unchecked primitive's nonfinite fallback is not an equivalence promise. The qualification admission rejects such values before calling either implementation.

Matrix/SRT/projection qualification requires finite inputs and intermediates, valid counts/indices and storage, positive selected dimensions and nonzero projection scales. Projection additionally requires a nonsingular pane-world matrix when coordinate source is four and flag four requests inversion. The original projection ignores inverse failure and consumes uninitialized temporary storage; this packet does not invent a matching result for that invalid case. The standalone inverse's zero-determinant behavior is qualified separately.

## Derived numeric data

`sine_table.inc` is generated by `toolscripts/native_wave014_table.py` from quarter-circle double-precision sine/cosine, quadrant symmetry and double-precision adjacent differences, then rounded to binary32 with canonical positive zeros. Differences must be computed **before** rounding the samples: the rejected rounded-sample subtraction differs in 252 entries of each slope column.

All 1,024 generated float bit patterns match the privately verified original 4,096-byte numeric table, SHA-256 `f2433a2419e313eb7d18fc5f2682c7be465840bf0f120094ab2b00c79dcca7a8`. The compiler-emitted constant is verified against the same recipe. No copied opaque original table, original executable data or post-compilation patch is retained in source execution.
