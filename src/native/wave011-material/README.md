# Complete material constructor candidate

This packet reconstructs update main-image function 0x00554a30 as ordinary typed C. Its complete ARM body occupies 3,020 bytes, from 0x00554a30 through 0x005555fc exclusive. Its two-word literal pool occupies the following eight bytes. The next function begins at 0x00555604. Four actual incoming branch-and-link sites corroborate the entry. This is a bounded behavior candidate, with zero requested exact matching bytes.

The constructor selects original, color-only replacement or complete replacement material resources from the context. It copies colors, walks every flag-selected wire record, bounds stage counts, requests runtime storage, initializes and resolves textures, copies transforms and coordinate generators, binds projection pointers, copies either simple or detailed combiners, and copies optional alpha, blend, projection and font-shadow records. The bit14 block affects wire offsets and the allocator argument but is not copied by this original constructor. Packed samplers and combiner parameters remain typed integer fields; this constructor copies those fields without interpreting their shader equations.

The original object is 132 bytes. The 104 bytes following its vtable and the three bytes after its property byte are preserved. Original ARM pointer layouts are statically asserted. Native pointer fields also allow subsequent service implementations to use their platform pointer width. The wire structs retain fixed scalar sizes. The volatile array-constructor function pointer preserves the measured ARM-to-Thumb interface when the private link resolves an absolute Thumb entry; it adds no assembly or executable bytes to the source.

Verification runs the complete immutable original function to its return and compares it with the genuinely compiled C function. Both use the original dependency bodies, including the Thumb array constructor, color constructor, storage/default initializer, texture helpers and their common GPU packing tail. Two explicit virtual services provide exclusive aligned heap memory or allocation failure, and immutable texture resources or null. Those deterministic services are test interfaces. The original heap thunk and lookup dispatch still execute normally. No original helper receives source credit.

There are 267 returning comparisons: 76 cover all 19 actual owner material records under four replacement modes; the remainder exercise structured boundaries, random resource flags, allocation failures and null resource lookups. The checks compare the full object, full allocated storage, dependency arguments and call order. They also check read/write domains, untouched guards, immutable inputs, integer and VFP callee-saved registers, stack restoration and both ARM and Thumb returns. Incoming flags, registers and storage are varied. Four separately compiled wrong C variants return normally while producing detected semantic differences in color selection, count clamping, projection linking or replacement selection.
